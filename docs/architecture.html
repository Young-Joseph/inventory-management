Architecture Reference

Factory Inventory Management

A demo full-stack inventory dashboard: a Vue 3 single-page app talking to a read-only Python FastAPI service that serves fixture JSON held in memory. There is no database, no persistence layer, and no authentication boundary.

Vue 3.4 + Vite 5 FastAPI + Uvicorn Python ≥ 3.11 / uv In-memory JSON fixtures branch: new_features

02System architecture

Two independent processes, started separately, that only meet over HTTP. The browser talks to Vite for assets and directly to FastAPI for data — there is no dev-server proxy, so the API origin is hard-coded in the client and the backend opens CORS to all origins to compensate.

Consequences worth knowing

Because fixtures load at import and are never written back, restarting the backend resets everything and no request can mutate state. Editing a file under server/data/ requires a backend restart to take effect — Uvicorn is started without --reload.

04Data flow — one filter change, end to end

The filter bar is the spine of the app: four controls whose state lives in a module-scoped singleton, so every view reads the same selection without prop threading.

  1. User changes a controlcomponents/FilterBar.vue
    Four selects — Time Period, Warehouse, Category, Order Status — bound with v-model to refs imported from the composable.
  2. Shared refs updatecomposables/useFilters.js
    The four refs are declared at module scope, outside the exported function, so every caller of useFilters() shares one instance. Default for each is the string 'all'.
  3. Views react and refetchviews/*.vue
    Each view watches the refs and calls getCurrentFilters(), which maps selectedLocation → warehouse and adds month only when a period is selected.
  4. Query string assembledapi.js
    Every 'all' value is dropped rather than sent, so an unfiltered request carries no query params at all — absence means "no filter" on both sides of the wire.
  5. FastAPI binds optional paramsserver/main.py
    Each handler declares Optional[str] = None for the filters it supports. Unsupported params are silently ignored by FastAPI rather than rejected.
  6. In-memory filteringapply_filters() → filter_by_month()
    apply_filters matches warehouse exactly and category/status case-insensitively. filter_by_month does a substring match on order_date, expanding Q1-2025…Q4-2025 through QUARTER_MAP.
  7. Pydantic validates the response
    List endpoints declare response_model, so a fixture whose shape drifts from the model raises a server-side validation error rather than reaching the client.
  8. Refs in, computed outviews/*.vue
    Responses land in raw refs (allOrders, inventoryItems); every derived total, chart series, and status rollup is a computed over those refs. Charts are hand-written inline SVG — no charting library.

Where the filter contract is uneven

/api/inventory accepts only warehouse and category. filter_by_month matches exclusively against an order_date key, and inventory records carry last_updated instead — so even though they do have a timestamp, the Time Period control has nothing to bind to on this collection. In /api/dashboard/summary, four of the five returned figures respect the active filters but total_backlog_items is computed from the unfiltered backlog_items list, so that tile never changes as filters move.

07Notable observations

Things that surprised me while reading, ordered by how likely they are to bite. These are observations, not changes — nothing here has been modified.

The client calls six endpoints that do not existconfirmed 404

api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder, and getPurchaseOrderByBacklogItem against /api/tasks and /api/purchase-orders. Neither path is registered in main.py — the backend has no non-GET route at all. App.vue calls api.getTasks() on mount, so the Tasks modal is wired to a dead endpoint.

Half-built purchase-order featuredead code

The PurchaseOrder and CreatePurchaseOrderRequest Pydantic models exist and purchase_orders.json is loaded, but no route reads or writes them. The single consumer is the has_purchase_order flag on /api/backlog, which is always false because the fixture is an empty array.

Reports.vue bypasses the API client

It imports axios directly and hard-codes http://localhost:8001/api/reports/... twice, against the "centralize API calls in api.js" rule in client/CLAUDE.md. It is the only place the base URL is duplicated, so pointing the app at a different backend means editing two files.

Backlog.vue is unreachable152 lines

The file is neither registered in the router nor imported anywhere. The dashboard renders its own inline backlog table instead, so this view appears to be a superseded leftover.

Dashboard.vue is far past the project's own extraction threshold

1271 lines, roughly a sixth of all frontend code, against a documented guideline of extracting at 100 template lines or 150 logic lines. It also carries repeated inline style="cursor: pointer;" across nine table cells that share one click handler.

Open CORS and no dev proxy

allow_origins=["*"] is combined with allow_credentials=True. That pairing is rejected by browsers for credentialed requests and is only harmless here because nothing sends credentials. A Vite server.proxy entry would remove both the wildcard and the hard-coded origin.

Deprecated uv configuration

server/pyproject.toml uses [tool.uv] dev-dependencies, which uv 0.12 warns about on every run; the current spelling is a [dependency-groups] dev list. Also worth noting: server/package-lock.json exists in a directory with no package.json.

08Running it

Two processes, two terminals. uv is a Python tool and must be installed separately — npm install only covers the frontend. 

# once, if uv is missing
brew install uv

# backend → http://localhost:8001  (docs at /docs)
cd server && uv run python main.py

# frontend → http://localhost:3000
cd client && npm install && npm run dev

# backend tests (40)
cd tests && uv run pytest

The repo also ships scripts/start.sh and scripts/stop.sh, mirrored by the /start and /stop Claude Code commands. The first uv run takes a minute while it creates server/.venv and resolves dependencies.
